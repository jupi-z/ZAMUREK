## Décisions normatives

**Garde-fous croisés (non négociables)** : identité staff/BUYER/AGENT séparée et future fédération OIDC/Monarque Auth sans migration de userId forcée ; une souscription active par produit, sans reprise ou élévation automatique de droits FairScale ; paiement POS via SalesOrder→Invoice canonique→PaymentRecord(invoiceId obligatoire)→CashMovement si espèces→Outbox, sans nouveau ledger ; permissions de caisse par commande et établissement. Validation des frontières Core avant Codex de la V1 ZAMUREK.

1. **Monarque Connect** est le Core propriétaire source de vérité pour Identity, RBAC, Organizations, Establishments, Product Entitlements/FairScale actuel, Item historique, SalesOrder/Invoice/PaymentRecord/CashAccount/CashMovement et Event Fabric. Les capacités catalogue commercial, pricing et FX partagées font l'objet du cadrage C3; elles ne sont pas déclarées runtime avant leur livraison. AI Gateway/Agent Runtime et fiscal documents restent futurs.
2. **ZAMUREK** est une identité **commerciale indépendante**, ses apps Android/Windows, son expérience découverte/mall opt-in et ses verticales (vente au poids, restauration, salon, meubles/devis, électronique-réparation, articles pharmaceutiques autorisés).
3. Les domaines métiers spécifiques qui nécessitent transactions et verrouillages avec les domaines Core sont développés en **modules NestJS isolés du Core Monarque Connect**, jamais comme duplication d'une DB/backend financier dans ZAMUREK. Les contrats et applications clients peuvent rester dans le dépôt ZAMUREK.
4. **Isolation multi-tenant V1 :** utiliser le modèle éprouvé `organizationId` + `establishmentId` dans PostgreSQL partagé de Monarque Connect, avec RBAC, object ownership, tests cross-tenant/cross-establishment et audits. L'ancienne exigence « une DB par organisation » est **RETIRÉE de la V1** ; déploiement dédié éventuel ultérieur sur décision séparée et migration démontrée.
5. Monarque Connect conserve le statut de source de vérité de **toutes ventes/factures/paiements/mouvements de caisse** ; ZAMUREK ne persiste que les modèles spécialisés et les projections publiques opt-in, jamais un deuxième ledger financier.
6. **POS en boutique = obligatoire V1** : passage client sans compte/e-mail (caissier authentifié), terminal/session, paiement cash, monnaie rendue, méthodes mixtes si validées, ouverture/clôture/écarts, retour, ticket/facture A4/58-80 mm et conformité fiscale fail-closed. Vente physique et online partagent commandes, journal de caisse et états canoniques.
7. **Prix ZAMUREK source USD vers CDF** reste une exigence de conception future, à fournir par le pricing Core après validation d'un taux autorisé; aucun prix ni taux commercial ZAMUREK n'est activé par C3.
8. **ZAMUREK BASIC 7 USD/mois/org** reste proposition de prix, avec capacité d'établissements/quotas/coûts à confirmer avant facturation réelle ; la souscription ZAMUREK **n'accorde pas** les droits ERP Business/Enterprise.
9. **Une seule Event Fabric, AI Gateway et Agent Runtime** : l'agent commercial ZAMUREK déclare outils/policies et appelle les use cases communs ; jamais d'agent propriétaire concurrent contournant Sales/Cash.
10. **Conventions d'API** : contrat canonique généré/versionné depuis le dépôt Core `Monarque-Connect` ; ZAMUREK conserve seulement le contrat client/projection et une traçabilité de version. Le `zamurek-v1.yaml` actuel est un **brouillon historique pré-convergence**, non une implémentation ni une autorité sur des endpoints existants.

## Déploiement / non-objectifs
Le backend commun reste API-only pour les clients ZAMUREK ; les APIs d'administration et d'exploitation sont protégées par authentification, autorisation et segmentation réseau adaptées, sans compter sur la visibilité du dépôt. Aucune SPA/SSR/portail marchand web ZAMUREK hébergé ; apps installables. LaJoie Mall n'est pas un partenariat acquis. Aucun Mercur/Medusa/Saleor, ERPNext/Frappe ; briques permissives vérifiées seulement. Facture normalisée DGI et pharmacie réglementée nécessitent validations/solutions officiellement autorisées ; pas de faux codes ou autorisations.
